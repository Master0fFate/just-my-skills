# Skill-pack audit and consolidation

## Result

**23 skills → 16: eight primary skills and eight on-demand Sexyness playbooks.**
Seven redundant entries were integrated into stronger owners. The external
frontend toolkit and its executable commands were removed, not renamed.

| Measure | Before | After |
| --- | ---: | ---: |
| Primary skills | 14 | 8 |
| Total SKILL.md entries | 23 | 16 |
| Core instruction words | 33,003 | 13,022 |

Core instructions are **60.5% shorter** by whitespace word count. This is a
context-size proxy, not a tokenizer benchmark or a measured model-quality gain.

The objective was clearer routing, lower instruction cost, preserved useful
methods, scoped authority, and verifiable outcomes—not the smallest possible
file count or a self-awarded perfect score.

### Why not merge everything?

Code changes, system boundaries, and runtime optimization have different evidence
requirements. They remain small, separately loaded playbooks rather than one
large engineering manual. The same applies to visual design, generated assets,
copy, and accessibility. Only the root is exposed automatically in Pi; the nested
entries remain explicitly usable through its supported discovery flag.

Angelcore retains a specific visual grammar and executable tools. Retrofit
retains migration/compatibility proof. Calibration requires explicit consent.
Explanation is a teaching deliverable. These are not duplicates of general polish.

## Corrections beyond merging

- Removed the forced 30% code-deletion target and mandatory PR/publish behavior.
- Removed false priority/session claims, profanity quotas, and unsupported claims
  that insults improve learning.
- Removed forced clarification/sign-off loops for harmless ambiguity.
- Stopped treating a planned test, exhausted budget, self-score, screenshot, or
  mock as proof of completion.
- Separated read-only review from authorized fixes, including metadata prompts
  and mutating test commands.
- Preserved existing line-breaking improvements; corrected unsupported browser
  algorithm guarantees and fixed engine limits under the later rewrite authorization.
- Preserved idea lineage, rare/emergency controls, source attribution, private
  profile approval, and compatibility requirements during consolidation.
- Added structural validation, its unit tests, routing/behavior cases, and kept
  useful prior refinement cases after correcting a false schedule-infeasibility
  expectation. Cases are specifications, not claimed live-model test passes.

## Executable Angelcore repairs

The static package audit now detects missing references, tests, and fixtures;
returns a structured failure for missing/invalid tokens or empty contrast coverage; and supports a
public package without the optional private screenshot. Private-reference
completeness can be required explicitly.

Browser tests now use sandboxing by default, a loopback-only HTTP server, no
server in offline mode, all four corner radii, visible four-sided border checks,
keyboard focus continuity, and script errors during interactive flows. The new
border detector was corrected after its first run wrongly flagged transparent
layout borders; a positive/negative browser fixture now tests that distinction.

Project/file selection restores keyboard focus after rerendering. Conversion
records include the source hash, crop, cell ratio, and supplied glyph coverage.
Source-overwrite checks also reject hardlink aliases. Browser checks explicitly
verify image decoding. The final independent review's malformed-URL,
parenthesized-path, and empty-contrast-coverage findings were fixed and given
regression tests; they are not outstanding defects.

## Verification and limits

Actual command results and environment are recorded in
[verification.json](verification.json). The final checks include:

- Metadata, unique names, catalog coverage, local Markdown targets, and JSON.
- Validator unit tests and Angelcore renderer/token/terminal tests.
- Fresh Chrome checks in both local-HTTP and offline modes, with sandbox enabled.
- JavaScript syntax, Python compilation, diff whitespace, and removed-toolkit
  residue checks.
- Independent read-only audits and a post-change review. The historical reviewer
  findings are in [audit-worker-review.md](audit-worker-review.md); later repairs
  and final dispositions are recorded here.

Known limits: the POSIX terminal/PTY test is skipped on Windows. The browser run
is Chrome, not a cross-browser, physical touch-device, screen-reader, or full WCAG
certification. Stored old screenshots are historical; they were not overwritten
or reused as current proof. No repeated installed-host/model study was run, so
this audit does not establish universal model reliability or a literal 10/10.
Remote DOI/background links were retained as unverified source pointers, not
newly checked evidence. The repository validator does not verify remote URLs
or every Markdown fragment anchor.

## Scope, compatibility, and attribution

Changes apply to this repository only. Global installed skills and reusable
`agents/` contracts were not edited. Replace installed folders deliberately and
remove retired copies outside this task; old slash commands are not automatic
aliases. Keep each maintained folder with its linked references and assets.

The initial uncommitted design changes and untracked Accelerate/Shipshape content
were inspected and backed up before edits. Their useful work was integrated,
not reset to HEAD. The complete initial skill tree is archived outside the
repository in the session's temporary baseline directory. No commit, push, or
publication was performed.
