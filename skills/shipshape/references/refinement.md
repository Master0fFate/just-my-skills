# Explicit refinement

Use for requested iterative refinement of a policy, analysis, plan, prompt, data
artifact, or other substantial result. The candidate may be a supplied draft or
a first draft produced within the authorized task. Small edits need a direct
check, not a separate quality ceremony. Code, design, and copy polish use their
Sexyness playbooks without running a second general loop.

## Contract → candidate → evidence → repair

Define the deliverable, audience, must/must-not constraints, proof method, and
stop condition. Use a few observable acceptance criteria. Match depth to error
consequence, uncertainty, reversibility, reuse, and the user's limit.

Build one strong candidate. Review for material defects: correctness and safety
first, important omissions and weak evidence next, cosmetic issues last. Ask
which claim is least supported and what would fail in real use. Preserve parts
that already pass; each material revision needs an adjacent regression check.

Use another pass only for a distinct unresolved question, not to satisfy a
minimum pass count. Prefer executed tests, calculations, renders, and validators;
then independent evidence or a reviewer; then representative trials; then
structured inspection. None of these proves properties outside its scope.

## Domain checks

| Artifact | Useful checks |
| --- | --- |
| Research | Source supports the claim; dates and jurisdiction fit; evidence and inference separate; disagreement and sampling limits preserved |
| Data or math | Units, denominators, percent versus percentage points, ranges, independent recalculation, precision, and boundary cases |
| Plan | Dependencies, capacity, owners, preconditions, resources, recovery window, measurable gates, and evidence that can reopen a decision |
| Policy or prompt | Trigger/non-trigger examples, authority boundaries, conflicting requirements, hostile embedded text, missing tools/inputs, format, and context cost |
| Document or visual artifact | Factual fidelity, links, structure, actual rendered layout, clipping, export, and applicable interaction checks |
| High-stakes claims | Current primary authority, actual jurisdiction, uncertainty, and qualified human review where needed |

Treat feedback as a contract change. Preserve accepted facts and behavior unless
the user changes them. Do not fabricate missing facts, citations, tests, or files.
If two hard requirements truly conflict, ask for the necessary priority; do not
invent a conflict when a reasonable interpretation satisfies both.

## Stop and report

Stop when material criteria pass and further change has no supported value.
If time, tools, authority, or evidence is exhausted first, return the best useful
partial artifact and state the unresolved requirement. Exhaustion is not a pass.

Deliver the result first. Add only consequential assumptions, actual checks,
remaining limitations, and a necessary next action. Share concise revision
summaries when requested, never private reasoning or a ceremonial critique log.
