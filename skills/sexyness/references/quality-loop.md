# Evidence and stopping rules

Use this reference for a substantial polish pass, a reusable artifact, or an explicit request to iterate. Small edits need only their decisive check.

Define the outcome, deliverable, audience, invariants, exclusions, evidence method, and stop condition. Choose observable acceptance criteria from the real task; attach a test, render, measurement, or inspection to each material criterion.

Build a strong candidate, then review it against those criteria. Fix incorrect, unusable, or misleading behavior first; fix important omissions and fragility next; apply cosmetic refinement last. Ask what would fail in actual use and which claim has the weakest evidence. Preserve parts that already pass.

Use focused passes for different uncertainties: correctness, resilience, visual coherence, or factual fidelity. After material edits, recheck the changed requirement and adjacent behavior. Batch related screenshots and fixes. Repeat only when a failure, new change, or unresolved concern justifies it; pass counts and arbitrary scores do not establish quality.

Prefer executed checks and real renders, then independent evidence, representative trials, and finally structured inspection. State when a claim rests only on inspection or an unmeasured complexity argument. Do not call unrun checks passed.

Stop when material criteria pass and remaining changes would be subjective or low value. If a check cannot run, report the specific limitation and its consequence. An exhausted budget is a limitation, not proof of completion.

For a review-only request, present evidence-linked findings in severity order and do not edit the artifact. A generic polish request does not authorize rewriting the product or expanding the task into a full audit.
